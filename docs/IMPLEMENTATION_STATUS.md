# Feature coverage

Implementation and tested scope as of 2026-10-12. Xenon can render the documented shared scene suite through CPU, software CUDA and OptiX. This is not support for arbitrary Blender graphs or every benchmark scene, nor a claim of physical or numerical equivalence to Cycles. Final scene measurements and images belong in [QUALIFICATION.md](QUALIFICATION.md); the earlier controlled scheduling experiment is recorded separately in [OPTIX_PERFORMANCE.md](OPTIX_PERFORMANCE.md).

| System | Concrete implementation and evidence | Supported boundary or remaining work |
|---|---|---|
| **Reproducible comparisons and measurements** | [main.cpp](../src/main.cpp), [measurement.h](../src/output/measurement.h) and [benchmark.py](../scripts/benchmark.py) provide explicit backend/64-bit seed, linear float32 PFM, PNG, settings/hardware metadata, dependency hashes, separate load/build/upload/render/readback/output timings, repeated-run spread, and optional sample-count/error curves. [measurement_test.py](../tests/measurement_test.py), [execution_test.py](../tests/execution_test.py), [sampler_test.cpp](../tests/sampler_test.cpp). | Backend requests fail rather than silently falling back. Time to a target error means the first **tested** sample count meeting that threshold, not an interpolated guarantee. Cycles model error can prevent convergence to the threshold. Host RSS is a peak; GPU memory figures are before/after free-memory snapshots, not a peak allocator trace. [Sampling evidence](SAMPLING.md) explains the corrected spatial seed correlation. |
| **Versioned scene/material contract** | [SCENE_CONTRACT.md](SCENE_CONTRACT.md), [MAT_FORMAT.md](MAT_FORMAT.md), [scene_file.cpp](../src/scene/scene_file.cpp), [material.cpp](../src/material/material.cpp) and [gpu_scene.cu](../src/cuda/gpu_scene.cu) define version 2, meters, axes, affine instances, UVs/normals, camera/light units, relative paths, texture color spaces and opacity/transmission. Unknown keys, invalid values and unsupported nondefault legacy specular fail. | Shared imported data is converted into backend buffers. The material model is custom and documented; OpenPBR is a design reference, not a conformance claim. Unsupported behavior is rejected at the parser/exporter boundaries described in the contract. |
| **Blender import/export and shared scenes** | [blender_export.py](../scripts/blender_export.py), [blender_import_scene.py](../scripts/blender_import_scene.py), [blender_prepare_scene.py](../scripts/blender_prepare_scene.py), [blender_bake_worker.py](../scripts/blender_bake_worker.py), fixture generators and [scene_assets.py](../scripts/scene_assets.py). [BLENDER_IMPORT.md](BLENDER_IMPORT.md) gives complete source/export/reference commands; [ASSETS.md](ASSETS.md) records pinned downloads and attribution. [blender_export_test.py](../tests/blender_export_test.py), [blender_import_test.py](../tests/blender_import_test.py). | Evaluated meshes, material bindings, corner normals, active UVs, cameras and selected lights/material graphs are supported; optional content-hashed native instances retain affine placements. Blender executes the source `.blend`; Xenon does not directly parse arbitrary `.blend` files. Procedural baking is an explicit conversion workflow, not a universal graph translator. Classroom uses the **same converted `comparison.blend` in both renderers**, with recorded closure, bake, light and camera changes; its original shading is not reproduced. Sponza retains fractional-alpha decals. Large assets stay outside version control. |
| **Textures and surface detail** | [mesh.cpp](../src/geometry/mesh.cpp), [texture.cpp](../src/material/texture.cpp), [material.cpp](../src/material/material.cpp), [gpu_traverse.cuh](../src/cuda/gpu_traverse.cuh): UV seams, exact sRGB decode, repeat/bilinear sampling, area-weighted mipmaps and explicit trilinear LOD; base-color/roughness/metallic/emission/opacity maps; tangent normal and bump maps. [texture_test.cpp](../tests/texture_test.cpp) and CUDA/OptiX wrappers cover evaluated hits and rendered fixtures. | Per-triangle UV derivatives preserve mirrored handedness but are **not MikkTSpace**. No automatic texture LOD/ray differentials or anisotropic filtering. PNG keeps 16-bit precision and HDR stays linear; EXR/UDIM are unsupported. Analytic primitives require constant materials. Native displacement is deferred; evaluated geometry may carry applied displacement. |
| **OptiX traversal** | [optix_backend.cu](../src/optix/optix_backend.cu), [optix_programs.cu](../src/optix/optix_programs.cu), shared [gpu_intersection.cuh](../src/cuda/gpu_intersection.cuh), and [OPTIX.md](OPTIX.md). Triangle GAS/instance IAS, stable IDs, transforms, finite shadows, analytic primitives and alpha-aware queries retain Xenon's wavefront shading. CPU/CUDA/OptiX geometry, texture, opacity and render tests compare the implementations. | NVIDIA/OptiX runtime support is required and checked. Infinite planes use an explicit analytic path. OptiX accelerates traversal; it does not replace Xenon's BSDFs or integrator. Final speedups must retain scene/hardware/settings and include startup/build/upload boundaries. |
| **Profile-driven scheduling** | [cuda_renderer.cu](../src/cuda/cuda_renderer.cu) uses device-resident queue counts and avoids per-bounce host counter reads; OptiX parameters are cached. [benchmark_gpu_scheduling.py](../scripts/benchmark_gpu_scheduling.py), [analyze_gpu_profile.py](../scripts/analyze_gpu_profile.py) and [OPTIX_PERFORMANCE.md](OPTIX_PERFORMANCE.md) retain controlled variants, exact-image checks and measured GPU uncovered intervals. | Per-sample synchronization preserves cancellation; preview publication is separate from headless final readback. Parameter caching alone did not establish an isolated timing gain. CUDA graphs, persistent kernels and display interoperability were not required by the measured changes and remain deferred. Earlier controlled results are not substituted for final-scene timings. |
| **Materials and lighting** | Shared [bsdf.h](../src/material/bsdf.h), [gpu_bsdf.cuh](../src/cuda/gpu_bsdf.cuh), [energy_lut.h](../src/material/energy_lut.h): optional GGX compensation, independent EON diffuse roughness, reciprocal approximate clearcoat and RGB absorption. [environment.h](../src/scene/environment.h), [scene.h](../src/scene/scene.h): HDR importance sampling, point/spot/directional sources, emissive triangles, two-sided emission, weighted light selection and MIS. [energy_test.cpp](../tests/energy_test.cpp), [cuda_bsdf_test.cu](../tests/cuda_bsdf_test.cu), environment/light-sampling/emission-sidedness tests. | GGX compensation is restricted to opaque isotropic materials with IOR in [1,3]. Clearcoat is energy bounded and reciprocal but omits internal layer returns; compensated rough-diffuse layering can lose white energy. [MATERIAL_ENERGY.md](MATERIAL_ENERGY.md) details these approximations. Sun is ideal directional, spot uses a documented cosine-cone convention, and area sources are triangles. **Sheen is not implemented**; its proposed addition was conditional on scene requirements, and unsupported nonzero imported sheen is rejected. No true subsurface transport or exact Blender Principled/OpenPBR model. |
| **Media and camera** | [medium.h](../src/volume/medium.h), [gpu_medium.cuh](../src/cuda/gpu_medium.cuh), [absorption.h](../src/volume/absorption.h), [camera.h](../src/camera/camera.h) and CPU/GPU transport implement RGB Beer absorption, homogeneous scattering, HG phase sampling, medium shadow extinction, circular aperture and focal distance. [medium_test.cpp](../tests/medium_test.cpp), [camera_test.cpp](../tests/camera_test.cpp), [transport_test.py](../tests/transport_test.py), [display_test.cpp](../tests/display_test.cpp). | Scattering media have nonoverlapping, axis-aligned **homogeneous box** boundaries; no heterogeneous fields or arbitrary volume shapes. Closed-surface absorption tracks at most eight enclosing materials, with explicit `camera_medium` for an interior camera. Fresnel/refraction still use **air/material IOR**, not exact nested dielectric interfaces. Display/PNG share exposure/Reinhard/sRGB while PFM remains linear. Polygonal apertures, spectral transport and advanced color-management transforms are not implemented. |
| **End-to-end qualification** | [suite.json](../scenes/benchmarks/suite.json) selects material studio, HDR studio, glass/fog, converted Classroom with instances, and full Sponza. [qualify_scenes.py](../scripts/qualify_scenes.py) validates inputs, runs [benchmark.py](../scripts/benchmark.py), preserves reference metadata and checks stable provenance. [QUALIFICATION.md](QUALIFICATION.md) owns the final images, comparisons and timing results. | Qualification applies to these sources and stated conversions. Linear backend agreement tests implementation parity; comparison with independently sampled Cycles also includes BSDF-model differences and reference noise. Native [material-study variants](MATERIAL_ENERGY.md#native-material-study) deliberately change materials and are not matched Cycles comparisons. BDPT and spectral rendering remain deferred as requested. |

The test inventory is frozen separately from scene timing runs: [CUDA/OptiX configuration](qualification/ctest-cuda-optix.log) passed 41 tests, [CPU-only configuration](qualification/ctest-cpu.log) passed 22, and [OpenGL output](qualification/ctest-opengl.log) passed its dedicated test. An earlier [targeted sanitizer run](qualification/sanitizer-targeted.log) passed five tests; the repaired thread pool additionally passed [ASan](qualification/thread-pool-asan.log) and [TSan](qualification/thread-pool-tsan-noaslr.log). These configurations overlap; their counts must not be added into a count of unique tests. They establish the tested cases, not exhaustive correctness of all scenes.

The exporter checks its supported material subset and rejects raw particle hair/path output, reduced particle preview density, mismatched child counts and render-dependent Geometry Nodes branches when using viewport evaluation. Mesh scatter retains visible placements of hidden prototypes. Focused scatter regressions compare the exported placements with Blender's render dependency graph. See [scatter and hair preparation](BLENDER_IMPORT.md#blendkit-scenes-and-grass).
